# 프롬프트 개선 서비스 디자인 기준
상태: 작성 중 (다음: 시안 화면 확인과 구현 기준 최종 승인)

## 공통 스타일 가이드
- 방향: 따뜻한 미니멀 화이트, 짙은 초록색 포인트, 큰 제목과 충분한 여백. 사용자의 "최적화해서 깔끔하게" 요청에 따라 AI 추천을 수용한 방향이다.
- 주 사용 기기: PC에서 비교를 넓게 보고 모바일에서도 이용할 수 있는 반응형. 모바일에서 단일 열을 기본으로, PC에서 원문·개선안 비교를 두 열로 확장한다. (추천 수용)
- 화면 제목: 제품 이름 미확정이므로 설명형 명칭 "프롬프트 다듬기"를 사용한다.
- 정보 우선순위: 현재 단계 → 화면 목적 → 입력·질문·결과 → 주요 버튼 → 부가 설명.
- 본문은 한국어로 작성하며, 주요 행동 버튼은 화면별 한 가지에 집중한다. 결과의 효능을 검증된 사실처럼 표현하지 않는다.
- 공통 단계 안내는 1 입력 / 2 의도 구체화 / 3 결과 비교로 표현한다. 질문의 횟수와 혼동되지 않도록 질문 라운드에는 백분율이나 고정 총횟수를 표시하지 않는다.

## 참고자료 적용표
| 참고자료 | 적용 | 복제 제외 |
|---|---|---|
| AI 추천 기준 | 읽기 쉬운 여백, 낮은 화면 밀도, 단계 안내, 초록색 주요 행동 버튼 | 외부 제품의 상표·이미지·문구를 복제하지 않음 |
| docs/prd.md | 3개 화면, 필요한 만큼 질문, 중간 생성, 결과 비교와 변경 이유, 브라우저 기록 | 로그인·결제·AI 답변 실행·모델 선택을 추가하지 않음 |

## 화면별 프롬프트 블록

### 1. 입력 화면
- 목적: 사용자가 자신의 말로 프롬프트를 입력하고 개선 과정을 시작한다.
- 주 사용 기기: PC와 모바일. 모바일 단일 열, PC에서 좌측 단계·최근 기록 영역과 우측 입력 영역.
- 공통 스타일: 따뜻한 흰색·짙은 초록 포인트, 한국어 산세리프 글자, 충분한 여백, 얇은 경계선, 부드러운 모서리.
- 요소: 제품 이름, 진행 단계, 제목과 한 줄 안내, 원문 입력칸, "함께 다듬기" 버튼, AI 전송 안내, 최근 작업과 개별·전체 삭제, 브라우저 보관 안내.
- 동작: 입력 후 질문 화면으로 이동. 정보가 이미 충분하면 실제 구현에서 결과로 바로 이동 가능. 빈 입력은 오류를 안내한다. 최근 완료 작업을 열면 결과로 이동하며 진행 중 작업은 질문으로 복귀한다.
- 모바일: 단계 안내를 상단의 짧은 텍스트로 바꾸고 최근 기록은 입력 영역 아래로 이동한다.

### 2. 질문·답변 화면
- 목적: 원래 의도를 유지하면서 필요한 맥락만 보완한다.
- 주 사용 기기: PC와 모바일. 한 열의 집중된 질문 영역과 상단 원문 요약.
- 공통 스타일: 따뜻한 흰색·짙은 초록 포인트, 한국어 산세리프 글자, 충분한 여백, 얇은 경계선, 부드러운 모서리.
- 요소: 입력한 원문, 지금까지 확인한 조건, 질문 1~2개와 질문 이유, 답변 입력, "답변하고 계속", "지금 개선하기".
- 동작: 답변에 따라 필요한 후속 질문을 표시한다. 정보가 충분하면 결과를 생성하며, 중간 생성 시 빠진 조건을 미정으로 남긴다. 모르는 답변을 강제로 입력하게 하지 않는다.
- 상태: 다음 질문 준비·결과 생성 중에는 상태 문구를 표시하고 중복 제출을 막는다. 오류 발생 시 입력한 답변을 유지하고 재시도할 수 있도록 한다. 이는 별도 화면이 아닌 기존 화면 내 상태다.
- 모바일: 입력칸과 버튼을 전체 폭으로 표시하며 가상 키보드가 나타나도 내용을 스크롤할 수 있게 한다.

### 3. 결과 비교 화면
- 목적: 무엇을 왜 개선했는지 확인하고 개선안을 복사해 사용한다.
- 주 사용 기기: PC와 모바일. PC에서 원문·개선안 병렬 비교, 모바일에서 원문 다음 개선안 순서.
- 공통 스타일: 따뜻한 흰색·짙은 초록 포인트, 한국어 산세리프 글자, 충분한 여백, 얇은 경계선, 부드러운 모서리.
- 요소: 원문, 개선 프롬프트, "개선안 복사", 번호가 있는 변경 이유, 실제 AI 답변 검증이 아니라는 설명, "새 프롬프트 시작".
- 동작: 복사 후 성공 안내를 표시한다. 복사 실패 시 텍스트를 직접 선택해 복사하도록 안내한다. 새 작업은 입력 화면으로 이동한다.
- 변경 이유: 실제 변경과 연결해 문제 → 바뀐 점 → 기대 효과를 설명한다. 점수·향상률 등 검증하지 않은 수치는 표시하지 않는다.

## 시안 산출물과 동작 범위
- 파일: `design/index.html` — 외부 라이브러리·이미지·폰트 다운로드 없는 단일 HTML 시안.
- 화면: `#input`, `#questions`, `#result`의 3개 상태. 하단 미리보기 링크는 시안 검토용이며 최종 제품에서는 제외한다.
- 고정된 여행 예시로 질문 2묶음과 결과 생성·복사·기록 삭제의 화면 동작을 확인할 수 있다. 실제 AI 질문이나 프롬프트 최적화 기능은 구현하지 않았다. 다른 내용을 입력해도 여행용 예시 질문을 표시하므로 범용 서비스 동작으로 해석하지 않는다.
- 시안의 최근 기록은 가짜 예시이며 영구 저장되지 않는다. 실제 브라우저 저장과 기록 20개 제한은 이후 기능 설계·구현 범위다.
- 화면별 캡처: `design/01-input.jpg`, `design/02-questions.jpg`, `design/03-result.jpg`.
- 모바일 캡처: `design/04-mobile-result.jpg`, `design/05-mobile-input.jpg`.

## 시안 분석과 확인 결과 (최종 승인 대기)
- PRD 화면 3개, 디자인 프롬프트 블록 3개, 실제 브라우저에서 확인한 시안 화면 3개로 대응한다.
- 입력: 큰 제목에서 입력 카드와 주요 버튼으로 시선이 이어진다. 부가 안내와 최근 작업은 주 입력 영역에서 분리되어 있다.
- 질문: 원문 요약 → 현재 질문과 이유 → 답변 입력 → 계속 버튼 순서다. 후속 질문에서는 앞선 답변 요약이 표시되는 것을 확인했다.
- 결과: PC에서는 원문과 개선안을 나란히 표시하고, 아래에 번호별 변경 이유를 둔다. 개선안 상단 경계선과 복사 버튼으로 주요 결과를 강조한다.
- 모바일: 결과 비교는 위아래로 배치하고, 최근 기록은 주 콘텐츠 아래로 이동한다. 입력·질문·결과 화면에서 가로 넘침이 없는 것을 확인했다. 결과·입력은 390px, 질문은 스크롤바를 제외한 콘텐츠 폭 375px에서 확인했다.
- 동작 확인: 원문 입력 → 첫 질문 → 답변 → 후속 질문과 요약 → 중간 생성 → 원문·개선안 비교 → 복사 성공 안내.
- 기록 삭제는 시안의 UI 예시이며 실제 저장·복구 정책을 검증한 것은 아니다. 로딩·실패 상태의 기준은 문서에 정의했으며 이번 시안에서 AI 연결 실패를 재현하지는 않았다.

## 도구 사용 안내
- HTML은 브라우저에서 열어 세 화면을 클릭해 확인한다.
- 외부 도구를 사용할 경우 Claude 유료 플랜 사용자는 Claude Design, 그 외에는 Google Stitch에 화면 블록을 하나씩 전달한다. 어색한 결과가 나오면 블록을 영어로 번역해 다시 시도할 수 있다.
- 현재 시안을 실제 구현 기준으로 사용할지 최종 확인한 뒤 문서 상태를 완료로 바꾼다.
